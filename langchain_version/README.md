# Семантический ИИ-ассистент по улучшению дипломных работ

Прототип для летней практики. Реализует три этапа из задания:

1. **Сегментация** (`segmenter.py`) — детерминированный парсер `.docx`, режет документ
   на Введение / Главы / Заключение / Список литературы по заголовкам Word (Heading 1)
   и по регуляркам (`config.py`).
2. **Кросс-анализ** (`analyzer.py`) — LLM (через LangChain, `Refine`-паттерн):
   - извлекает структурированные тезисы из Введения (цель, задачи, гипотеза) → JSON;
   - извлекает структурированные тезисы из Заключения (результаты, вердикт по гипотезе) → JSON;
   - сверяет два коротких JSON друг с другом (а не весь текст диплома целиком —
     это и есть защита от галлюцинаций на длинных документах).
3. **Стилистический фильтр** (`style_filter.py`) — два слоя:
   - быстрый regex-анализ по словарю канцеляризмов/штампов/инфоцыганства
     (аналог метрики Главреда, считается без единого вызова LLM);
   - опциональный рерайт самых "грязных" предложений через LLM.

## Почему так, а не "закинуть весь диплом в один промпт"

На 30-60 страницах модель либо обрежет контекст, либо начнёт "додумывать" связи,
которых нет в тексте (классическая галлюцинация на длинном контексте). Поэтому:

- Сегментация — **без LLM**, чистый парсинг, 100% детерминированность.
- Анализ воды — **без LLM**, чистые регулярки, KPI считается объективно.
- LLM используется только там, где реально нужна семантика (сопоставление целей
  и результатов, гипотеза), и всегда получает **маленький, точечный кусок текста**,
  а не весь документ.

## Установка

```bash
cd diploma_assistant
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...   # ключ для LLM-этапов
```

## Запуск

```bash
# Полный анализ (сегментация + вода + LLM-сверка логики)
python main.py моя_диплома.docx --output report.md

# Только быстрый анализ воды, без обращений к LLM (бесплатно, мгновенно)
python main.py моя_диплома.docx --no-llm

# Полный анализ + переписать самые водянистые предложения
python main.py моя_диплома.docx --rewrite
```

Результат — файл `report.md` с разделами:
1. Структура документа (сколько слов в каждой части)
2. Логическая связность Введение ↔ Заключение (по каждой задаче — выполнена/нет,
   вердикт по гипотезе, оценка логики 0-10, список конкретных нестыковок)
3. Стилистический анализ (индекс воды по каждому разделу, разбивка по категориям штампов)
4. (опционально) Было/стало для переписанных предложений

## Важное ограничение прототипа

Сегментация полагается на то, что в дипломе используются стандартные заголовки
Word ("Введение", "Глава 1", "Заключение" и т.п. как отдельный абзац или Heading-стиль).
Если студент оформил заголовки нестандартно (например, вставил их как картинку
или использовал произвольные названия глав), нужно расширить `SECTION_PATTERNS`
в `config.py` — это одна из точек роста проекта для практики.

## Дальнейшее развитие (что можно добавить для расширения работы)

- Проверка Главы 1 vs Главы 2 (согласуется ли практическая часть с теоретической базой).
- Проверка списка литературы на актуальность (год изданий) и на реальное цитирование
  источников в тексте (упоминается ли автор из списка литературы хоть раз в тексте).
- Замена regex-словаря клише на ML-классификатор (нужна размеченная выборка).
- Веб-интерфейс (Streamlit/Gradio) вместо CLI для удобства студента.
- Кэширование JSON-ответов LLM по хэшу текста раздела — не гонять API повторно
  при повторном запуске на том же файле.
